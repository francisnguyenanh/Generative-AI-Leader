## Slide 9: 生成 AI エージェントの構成要素 - 基盤モデル・ツール・推論ループの三位一体により、単なる対話型モデルを超えた自律的タスク遂行を実現

| 要素 | 内容 |

| 01 基盤モデル | - エージェントを支える基盤となる大規模言語モデル（LLM）<br>- 意図されたユースケースに関連するデータでトレーニングされたモデルを選択<br>- 小規模・大規模モデル、Gemini などの Google 製および外部モデルを用途に応じて適用 |

## Slide 14: サンプリング パラメータと設定

| パラメータ | 役割 | 説明 |
|---|---|---|
| トークン数 | テキストの基本単位と処理容量 | 1 トークン ≅ 4 文字。一度に扱える情報量と必要計算リソースの上限を規定 |
| 温度（Temperature） | 単語選択のランダム性と創造性の制御 | 低値で決定的・再現性重視（Q&A）、高値で多様・予想外な表現（創作） |
| Top-K | 確率上位 K 個からのランダム選択 | 単語候補を上位の決まった個数に限定し、極端に不適切な単語の混入を防止 |
| Top-P（Nucleus サンプリング） | 累積確率に基づく動的な候補の絞り込み | 確信度に応じて候補数を伸縮させ、整合性とバリエーションを両立 |
| 安全性設定 | 有害・不適切な出力のフィルタリング | ニーズやコンプライアンスに応じてカテゴリ別のブロック基準を調整 |
| 出力長（Max Output Tokens） | 生成されるテキストの最大長を決定 | 単語数や最大トークン数を指定し、簡潔な回答維持やコスト消費をコントロール |

## Slide 15: 温度（Temperature）と Top-P - モデルの「決定性（事実性）」と「多様性（創造性）」を制御する仕組みと、試験で問われる使い分けの鉄則

温度スケール: 0.0（事実性・再現性の最大化）←→ 1.0（創造性・多様性の最大化）

- 0.0 側: 決定的な回答 / 確実なタスク向け。確率の差を極端に強調し、常に最も確率の高い単語を選択（再現性 100% の Greedy Search に近い）。構文エラーを嫌うコード生成や事実のみを答える Q&A に最適。
- 1.0 側: 意外性のある表現 / 斬新なアイデア創出向け。確率分布をなだらかにし、低確率の言葉もサンプリング対象に。表現の幅が広がりユーモアや物語を生む一方、ハルシネーション（事実誤認）のリスクが増加。

試験対策：タスク別推奨パラメータ設定マトリクス

| タスク | 💻 コード生成 / 事実ベース回答 | 📄 要約 / データ抽出 / 翻訳 | ✨ 広告コピー / 創作 / ブレスト |
|---|---|---|---|
| 特徴 | 厳密な論理、一貫性、バグのなさが絶対条件となる再現重視タスク | 原文の文脈を完全に保持しつつ、自然な表現のゆらぎを取り入れるタスク | ありきたりではない語彙、斬新なアイデア、多様な切り口を求めるタスク |
| 推奨値 | Temperature: 0.0 〜 0.2 / Top-P: 0.1 〜 0.5 | Temperature: 0.2 〜 0.5 / Top-P: 0.7 〜 0.8 | Temperature: 0.7 〜 1.0 / Top-P: 0.9 〜 0.95 |
| 鉄則 | 迷ったら即座に Temperature=0 を選択 | 事実性と表現のなめらかさのバランス調整 | 不自然な単語を省きつつ創造性を最大化 |

## Slide 17: Google の生成 AI ツール：選定と使い分け - 開発フェーズと統制要件に合わせて、2つの環境を最適に使い分けます

- Google AI Studio（Web ベース / 即時検証）: 対象は開発者・学生・研究者。アイデアを形にするためのエントリー環境。API キーを即座に発行し、Gemini の性能を素早くテスト。
- Agent Studio（Google Cloud / 本番・統制）: 対象は企業組織・ML エンジニア・エンタープライズ開発者。セキュリティと組織管理（IAM）を担保した本番運用向け環境。高度なチューニングや各種システムとの安全な統合をサポート。
- 移行のトリガー（AI Studio → Agent Studio）: 本番運用への実装 / 厳格なガバナンス / モデルの独自調整

| 比較項目 | Google AI Studio（プロトタイプ向け） | Agent Studio（エンタープライズ向け） |
|---|---|---|
| 実行基盤 & アクセス | Web ブラウザ経由、標準の Google アカウントで即座に開始可能 | Google Cloud コンソール内、GCP プロジェクト配下で利用 |
| ガバナンス & セキュリティ | 手軽な検証・個人開発に最適な基本構成 | 組織ポリシー準拠、IAM による詳細なアクセス制御、エンタープライズ基準 |
| 主要な機能と連携 | プロンプト実験、検証、Gemini API コードの即時取得 | 基盤モデルのチューニング、グラウンディング、容易なデプロイ |
| 割り当て & 料金体系 | 利用量に上限あり（無料枠を中心としたプロトタイプ設計向き） | 柔軟な割り当て調整、企業の商用利用に合わせた従量課金システム |

💡 実践のベストプラクティス: まずは Google AI Studio で素早くプロトタイプ検証を行い、本番運用や厳格なガバナンスが必要になった段階で Agent Studio へ移行するのが最適です。

## Slide 20: プロンプト エンジニアリングの手法

- Chain-of-Thought（CoT）: 問題解決のプロセスに沿って言語モデルを誘導するために、中間の推論ステップを例で示すという手法。
- ReAct（推論と行動）: コンテキストに沿った例の有無にかかわらず、言語モデルがユーザーのクエリに基づいて推論し、行動できるようにするためのプロンプト フレームワーク。

---

## Slide 21: Chain-of-Thought（CoT）

- CoT は中間ステップを通じて推論能力を発揮できるようにする。
- LLM に単にプロンプトを渡して回答を期待するのではなく、推論プロセスに沿ってLLM を導く。
- 中間ステップは、正解へと導く「思考の連鎖」。

## Slide 23: CoT の実装方法

| 自己整合性 | 積極的なプロンプティング | マルチモーダル CoT |
|---|---|---|
| 複数のソリューションを生成し、その中から最も整合性の高い解を選択するよう促す | LLM が明確化のための質問や追加情報を自律的にリクエストできるようにする | 推論を強化するために、テキストに画像や動画などの多様なデータを組み合わせる |
| 多様な推論パスを並行して展開し、多数決による合意形成を行う | 前提条件が曖昧な場合に独断で進めず、能動的に確認・対話 | 図表、ダイアグラム、映像フレームなどの非言語コンテキストを思考ステップに統合 |
| 推論の誤りやランダムなハルシネーションを大幅に抑制 | ユーザー意図との齟齬を解消し、回答の正確性を向上 | 高度な空間認識や視覚的証拠に基づく判断を実現 |

## Slide 24: CoT が重要である理由

- 推論機能の強化: LLM が論理的思考を必要とする複雑な問題を解決するうえで役立つ。
- 精度の向上: 問題を小さなステップに分割すると、より精度の高い結果につなげることができる。
- 説明可能性の強化: LLM が回答にたどり着くまでの道筋が理解しやすくなり、信頼性と透明性が高まる。

## Slide 26: ReAct の主な構成要素

ReAct を使用すると、LLM が実世界とやり取りして情報を収集できる。

構成要素（タイムライン上の順）: 思考 → 行動 → 観察 → 応答（詳細は次スライド）

---

## Slide 27: ReAct の主な構成要素

| 要素 | 内容 |
|---|---|
| 思考 | LLM が問題に関する思考を生成する。 |
| 行動 | LLM が取るべき行動を決定し、その行動に必要な入力を指定する。 |
| 観察 | 行動の結果として、LLM がフィードバックを受け取る。 |
| 応答 | LLM が応答を生成する。 |

---

## Slide 28: ReAct: 「思考 - 行動 - 観察」ループ

ループの流れ: 思考 → 行動 → 観察 → 思考 → 行動 → 観察 → … → 応答（観察の結果、十分な情報が得られたら応答を生成）

---

## Slide 29: ReAct: 「思考 - 行動 - 観察」ループの例

1. 思考: この辺りにあるイタリア料理のレストランを見つけるよう要求されている。
2. 行動: この地域のイタリア料理レストランをオンラインで検索しよう。
3. 観察: 評価の高い候補がいくつか見つかった。
4. 思考: ユーザーの好みからすると、どの候補が最適だろう。
5. 行動: メニューを見て、とりわけおいしそうな料理を提供しているレストランを選ぼう。
6. 観察: ここでは、おいしそうなパスタ料理を提供している。
7. 応答: [名前] をおすすめします。高い評価を受けていて、近くにあり、パスタ料理の種類も豊富なレストランです。

---

## Slide 30: ReAct が重要である理由

- 動的な問題解決: 外部リソースとやり取りして新しい情報に適応する必要がある複雑なタスクでも、LLM が対処できるようになる。
- ハルシネーションの低減: グラウンディングにより、誤った情報や意味不明な情報を生成するリスクが軽減される。
- 信頼性の向上: LLM の推論プロセスと外部ソースとのやり取りを可視化できるため、応答の透明性と信頼性が高まる。

## Slide 36: 推論ループとツールが連動する仕組み

1. 推論: エージェントがタスクを分析し、必要なツールを判断する。
2. 行動: エージェントが選択したツールを実行する。
3. モニタリング: エージェントがツールから出力を受け取る。
4. 反復: エージェントが次のステップについて推論する。（→ 1. に戻る）

## Slide 54: モデルと RAG が連携する仕組み - 検索拡張生成（Retrieval-Augmented Generation）における 3 つの基本ステージと反復サイクル

RAG とは: LLM の回答を外部の知識源に根拠づける（グラウンディング）技術。最新情報や社内データを取り込み、正確な回答を実現。（効果: ハルシネーション抑制 / 最新データ即時反映 / 出典・根拠の明記）

| ステージ | 内容 |
|---|---|
| Step 01 / Retrieval 取得 | ユーザーの質問をもとに、検索ツールを備えた LLM が外部ソースから関連情報を探索・特定します。 |
| Step 02 / Augmentation 拡張 | 取得した関連情報をプロンプトへ組み込み、LLM が文脈を理解できるよう入力を強化します。 |
| Step 03 / Generation 生成 | 拡張されたプロンプトを LLM が処理し、事実に基づいた正確で文脈に沿った回答を出力します。 |

主な検索ツールとソース:
- データストア: 社内 DB・ファイル等
- ベクトル DB: 類似度高速マッチ
- 検索エンジン: Web 公開情報
- ナレッジグラフ: 関係性・事実データ

プロンプトの統合イメージ: ユーザーの元の質問 ＋ 検索で得た関連文脈 → 拡張プロンプト（Augmented Prompt）。モデルの再学習なしで、固有の背景知識や最新の事実をプロンプト経由で動的に注入。

出力のメリットと特徴:
- ✔ 高い精度と適合性: 事実コンテキストに沿って的確に推論
- ✔ 出典の透明性: 参照した情報源（URL・文書）を明記し検証を容易化
- ✔ 再学習コスト不要: 巨大な基盤モデルを再学習させずに常に最新化

発展：反復（Iteration）: 初回検索で十分な情報が得られない場合、クエリの自動再調整・別ツールの併用・ユーザーへの確認質問を行い、回答の品質を継続的に向上させる。

## Slide 56: RAG の例: 最近の出来事に関する質問に答える

1. ユーザーのクエリ:「ドバイで最近開催された気候に関する会議での主な進展は何ですか」
2. 取得: LLM が関連情報を求めて、ベクトル データベースと検索エンジンに対するクエリを実行する。
3. 拡張: LLM がユーザーのクエリに、取得した情報を組み合わせる。
4. 生成: LLM が気候会議の主な進展を要約した回答を生成し、その情報源を引用する。
5. 繰り返し: LLM が別の検索キーワードを試したり、他のデータソースをクエリしたりする場合もある。

## Bổ sung kiến thức ôn thi (Claude)

> Phần này do Claude bổ sung, KHÔNG nằm trong PDF. Tên sản phẩm Google Cloud đổi tên khá thường xuyên (deck dùng "Agent Studio / Agent Platform" cho thứ trước đây gọi là Vertex AI Studio / Vertex AI) – đề thi thật có thể dùng tên cũ hoặc mới, hãy nhận ra cả hai.

### 1. Agent (エージェント) vs chatbot vs workflow
| | Chatbot truyền thống (決定論的) | Gen AI agent |
|---|---|---|
| Cách hoạt động | Luật / kịch bản định sẵn, intent-flow | LLM suy luận, tự chọn tool để đạt mục tiêu |
| Thành phần | Reasoning loop + tools (không có foundation model) | Foundation model + tools + reasoning loop (orchestration) |
| Ưu | Dễ kiểm soát, dự đoán được | Linh hoạt, xử lý yêu cầu mơ hồ, đa bước |
| Nhược | Cứng, không hiểu ngữ cảnh mới | Khó kiểm soát hơn, có rủi ro hallucination |

Hybrid (CX Agent Studio): dùng luật cho phần cần chính xác/tuân thủ + gen AI cho phần hội thoại tự nhiên. Multi-agent system: nhiều agent chuyên biệt phối hợp cho mục tiêu phức tạp (khác với 1 agent dùng nhiều tool).

### 2. Các loại tool của agent (hay nhầm)
- Extension (拡張機能): agent gọi API bên ngoài trực tiếp, chuẩn hóa cách gọi API.
- Function (関数): model chỉ *đề xuất* tên hàm + tham số (function calling); phần mã thực thi chạy phía client/ứng dụng, không phải do model chạy.
- Data store (データストア): nguồn tri thức (web, DB có cấu trúc, tài liệu phi cấu trúc) cho RAG.
- Plugin: mở rộng kỹ năng/tích hợp với dịch vụ ngoài (lịch, thanh toán).
- Pitfall: đề Q4 (đặt lịch họp: truy cập calendar + gửi lời mời) đáp án là Extension + Plugin vì cần *hành động ra hệ thống ngoài*; Data store/Function thiên về truy xuất dữ liệu / logic nội bộ.

### 3. CoT vs ReAct vs Self-consistency
| Kỹ thuật | Ý chính | Dùng khi |
|---|---|---|
| Chain-of-Thought | Hướng dẫn model nêu từng bước suy luận trung gian | Bài toán logic/số học, cần giải thích được |
| ReAct | Vòng lặp Thought → Action → Observation, gọi tool bên ngoài | Cần thông tin thời gian thực / thực hiện hành động |
| Self-consistency | Sinh nhiều đường suy luận, chọn đáp án đa số | Tăng độ tin cậy suy luận |

Nhớ: CoT = suy nghĩ nội bộ; ReAct = suy nghĩ + tương tác bên ngoài. Hai cái có thể kết hợp.

### 4. Tham số sinh (sampling)
- Temperature thấp = xác định, nhất quán (code, Q&A sự kiện); cao = sáng tạo nhưng dễ hallucination.
- Top-K: chỉ chọn trong K token xác suất cao nhất (số cố định). Top-P: chọn tập token nhỏ nhất có xác suất tích lũy ≥ P (số động).
- Max output tokens giới hạn độ dài/chi phí; safety settings lọc nội dung độc hại. Đề thi chỉ hỏi "tham số nào điều khiển tính ngẫu nhiên/sáng tạo" = Temperature.
- Các giá trị khuyến nghị theo task ở slide 15 là gợi ý của deck, không phải quy chuẩn tuyệt đối.

### 5. RAG vs Fine-tuning vs Grounding
| | RAG | Fine-tuning | Grounding |
|---|---|---|---|
| Bản chất | Truy xuất tài liệu rồi đưa vào prompt | Huấn luyện thêm, đổi trọng số model | Khái niệm rộng: neo câu trả lời vào nguồn thực (RAG, Google Search, dữ liệu doanh nghiệp) |
| Dữ liệu mới | Cập nhật tức thì, không cần retrain | Phải train lại | Tùy phương pháp |
| Trích dẫn nguồn | Có | Không mặc định | Có (citation) |
| Chi phí | Thấp hơn | Cao hơn | - |
Quy tắc: cần dữ liệu mới / nội bộ + giảm hallucination + dẫn nguồn → RAG/grounding; cần đổi phong cách/giọng/chuyên ngành sâu → fine-tuning. 3 bước RAG: Retrieval → Augmentation → Generation. Vector database dùng embedding để tìm theo ngữ nghĩa (độ tương đồng), không chỉ từ khóa.

### 6. Sản phẩm Google Cloud liên quan (cần nhớ vai trò)
| Sản phẩm | Vai trò |
|---|---|
| Google AI Studio | Prototype nhanh, API key Gemini, người dùng cá nhân/dev; không phải môi trường quản trị doanh nghiệp |
| Agent Studio / Vertex AI (Agent Platform) | Môi trường doanh nghiệp: IAM, tuning, grounding, deploy; Model Garden (nhiều model Google + bên thứ ba + open) |
| Agent Search (Vertex AI Search) | Tìm kiếm doanh nghiệp theo kiểu Google + grounding/RAG làm sẵn, tóm tắt kết quả, hỏi đáp tiếp |
| Gemini Enterprise (trước đây Agentspace) | Nền tảng tập trung cho nhân viên: tìm kiếm trên dữ liệu công ty + tạo/chạy agent; (nên xác nhận tên hiện hành khi thi) |
| Gemini Enterprise for CX / CX Agent Studio / Customer Engagement Suite | Chatbot/voicebot (hybrid), Agent Assist (hỗ trợ nhân viên tổng đài theo thời gian thực), CX Insights (phân tích hội thoại), CCaaS |
| Agent Development Kit (ADK), Agent2Agent (A2A), Model Context Protocol (MCP) | Framework/giao thức mở xây agent, agent giao tiếp với agent, kết nối tool/dữ liệu chuẩn hóa (đề Leader ít hỏi sâu, nên biết tên) |

Pitfall: Agent Assist hỗ trợ *nhân viên (con người)*, không phải chatbot đối mặt khách; CX chatbot là phía khách. Search for commerce / media recommendations là giải pháp chuyên ngành (bán lẻ / media).

### 7. Business strategy (15%): lộ trình áp dụng
Vision & sponsor → ưu tiên use case có tác động cao & khả thi → đầu tư kỹ năng → quản trị thay đổi → đo KPI/ROI lặp lại → Responsible AI (công bằng, minh bạch, quyền riêng tư, bảo mật). Đáp án sai điển hình: "bỏ qua đạo đức", "chỉ tập trung công nghệ, hiệu quả sẽ tự đến", "chỉ mục tiêu ngắn hạn".

### 8. Câu hỏi ôn (tự luyện)
1. Thành phần cốt lõi của agent? → Foundation model, tools, reasoning loop (orchestration).
2. Muốn agent trả lời theo tài liệu nội bộ mới nhất mà không retrain, có dẫn nguồn? → RAG (data store + Agent Search/grounding).
3. Agent cần tra cứu giá cổ phiếu thời gian thực rồi quyết định bước tiếp → ReAct (Thought-Action-Observation), tool = extension/API.
4. Team đã prototype xong trên AI Studio, nay cần IAM, tuning, chính sách tổ chức → chuyển sang Agent Studio/Vertex AI trên Google Cloud.
5. Cần kiểm soát chặt hành vi nhưng vẫn hội thoại tự nhiên → agent hybrid (deterministic + generative).
6. Sinh code, ưu tiên đầu ra nhất quán → Temperature thấp (gần 0).

### Bổ sung theo Exam Guide chính thức (mục 2.3, 2.4, 2.5, 3.3)

> Nguồn: exam guide và study guide chính thức. Chi tiết xem `exam-guide-official-checklist.md`.

- **Customer Engagement Suite:** Conversational Agents/CX Agent Studio (chatbot khách hàng), **Agent Assist** (hỗ trợ nhân viên đang trực tiếp nói chuyện), **Conversational Insights** (phân tích toàn bộ giao tiếp với khách), **CCaaS** (contact center cloud-native, nền cho các công cụ trên).
- **RAG APIs** và **pre-built RAG với Agent Search** là 2 offering RAG của Google Cloud.
- **Truy cập Gemini API:** Cloud Run functions, Cloud Run; low-code/no-code: **Apps Script**, **AppSheet**.
- **4 loại tooling của agent:** Extensions (nối dịch vụ ngoài qua API), Functions (hành động cụ thể), Data stores (truy cập thông tin), Plugins (thêm kỹ năng/tích hợp).
- **3 loại agent:** Deterministic (đường đi định sẵn), Generative (định nghĩa bằng ngôn ngữ tự nhiên), Hybrid (kết hợp cả hai).
- **API dựng sẵn cho tooling:**

| API | Làm gì |
|---|---|
| Speech-to-Text | Giọng nói → văn bản, phiên âm audio/video |
| Text-to-Speech | Văn bản → giọng nói tự nhiên |
| Translation | Dịch văn bản, tài liệu, website, audio/video |
| Document Translation | Dịch tài liệu có định dạng, giữ nguyên layout |
| Document AI | Trích xuất dữ liệu từ tài liệu, tự động hóa xử lý, tóm tắt |
| Cloud Vision | Phân tích ảnh (vật thể, chữ, khuôn mặt, địa danh), kiểm duyệt, tìm kiếm trực quan |
| Cloud Video Intelligence | Phân tích video, gợi ý nội dung, tìm video |
| Natural Language | Sentiment, phân loại nội dung, trích xuất entity |

- **Google AI Studio vs Agent Studio:** AI Studio miễn phí, prototype nhanh; Agent Studio xây và triển khai ứng dụng production quy mô lớn.
