## Slide 26: グラウンディングとは

グラウンディング（Grounding）とは、AI モデルの出力を**検証可能な特定の情報源**に紐づけることで、回答の正確性と信頼性を高める機能です。

| AI モデルの出力 | ⇄ 紐づけ・検証 ⇄ | 検証可能な情報源 |
|---|---|---|
| ユーザーの指示に対して生成された回答。外部データと連携しない場合、事実に基づかない誤った情報（ハルシネーション）が含まれる可能性があります。 | | 社内ドキュメント、データベース、一次情報などの信頼できるデータ群。生成された回答が正しいファクトに基づいているかを検証する基準となります。 |

---

## Slide 27: 検索拡張生成（RAG）

| 01 関連情報の取得 | → | 02 出力の生成 |
|---|---|---|
| AI モデルが膨大なナレッジベースから関連情報を取得します。 | | 取得された情報を使用して、モデルが最終的な出力を生成します。 |

---

## Slide 28: 検索拡張生成（RAG）

図の内容:

- **モデルのみ（RAG を使用しない場合）**: ユーザー → プロンプト → モデル → 出力 → ユーザー
- **RAG を使用した場合のモデル**: ユーザー → プロンプト → モデル →（クエリ）→ ベクトル DB →（関連情報をモデルへ返す）→ モデル → 出力 → ユーザー

## Slide 48: 保存された情報

生成 AI ツールに会話のコンテキストを記憶させたい一方、会話の履歴全体を記憶させたいわけではない場合は、[保存された情報] の [設定] を調整する。
例
- あなたは営業担当者として、見込み顧客との通話に備えて準備しているとします。さまざまなセールスピッチを練習したいものの、以前の練習セッションや過去のクライアントに関する特定の詳細によって、AIのフィードバックが影響されないようにしなければなりません。
- この場合、Gemini に、自分が営業担当者であることを把握させることができます。

## Bổ sung kiến thức ôn thi (Claude)

> Phần này do Claude bổ sung, KHÔNG nằm trong PDF. Các mục ghi "(chưa chắc)" nên đối chiếu tài liệu Google Cloud mới nhất (tên sản phẩm đổi thường xuyên).

### 1. Các kỹ thuật prompt (Domain: Techniques to improve output)
| Kỹ thuật | Ý nghĩa | Khi dùng |
|---|---|---|
| Zero-shot | Không có ví dụ, chỉ chỉ thị | Tác vụ đơn giản, phổ biến |
| One-shot / Few-shot | 1 / nhiều ví dụ trong prompt | Cần cố định format, giọng văn |
| Role prompting (ロール) | Gán persona -> đổi style, tone, focus | Chăm sóc KH, copywriting |
| Prompt chaining (プロンプト チェーン) | Chuỗi prompt, output trước làm ngữ cảnh cho sau | Tác vụ nhiều bước, tinh chỉnh dần |
| Chain-of-Thought (CoT) | Yêu cầu suy luận từng bước | Bài toán logic/tính toán nhiều bước |
| Prompt kèm context/ràng buộc/format | Nêu rõ mục tiêu, đối tượng, định dạng đầu ra | Luôn nên có |

Hay nhầm: few-shot/zero-shot KHÔNG huấn luyện lại mô hình (không đổi trọng số); chỉ là in-context learning trong prompt.

### 2. Grounding vs RAG vs Fine-tuning
| | Grounding | RAG | Fine-tuning (微調整) |
|---|---|---|---|
| Bản chất | Gắn output vào nguồn kiểm chứng được (kết quả: giảm hallucination, có citation) | Một cách hiện thực grounding: truy xuất (retrieve) tài liệu liên quan -> đưa vào prompt -> sinh | Huấn luyện thêm mô hình trên dữ liệu riêng |
| Dữ liệu mới nhất | Có | Có (chỉ cần cập nhật kho dữ liệu) | Không tự cập nhật, phải train lại |
| Chi phí | Thấp | Thấp-vừa | Cao hơn |
| Dùng khi | Cần chính xác, có dẫn nguồn | Tri thức nội bộ, thay đổi thường xuyên | Cần thay đổi phong cách/hành vi/chuyên ngành sâu |

- RAG = embeddings + vector database + semantic search (ngoài ra có thể kết hợp full-text/hybrid search). Grounding có thể dùng Google Search hoặc dữ liệu doanh nghiệp (ví dụ qua Vertex AI Search / Agent Search; tên sản phẩm có thể đã đổi - chưa chắc).
- Hay nhầm: "Grounding chỉ có trong Gemini Notebook" là SAI (slide 60-61). Gemini Notebook (trước đây NotebookLM) chỉ dùng nguồn người dùng upload, không tự lên internet.

### 3. Google Workspace with Gemini vs Gemini app vs Gemini for Google Cloud
| Sản phẩm | Dành cho | Ví dụ |
|---|---|---|
| Gemini app (gemini.google.com) | Cá nhân/nhân viên, chat đa dụng | Gem, Saved info (保存された情報), Deep Research |
| Gemini trong Workspace (Gmail, Docs, Sheets, Slides, Meet, Drive) | Nhân viên văn phòng, năng suất | Soạn mail, công thức Sheets, dịch/ghi chú Meet |
| Gemini Notebook (NotebookLM) | Nghiên cứu dựa trên nguồn đã upload | Tóm tắt, quiz, audio overview |
| Gemini for Google Cloud | Developer, vận hành, data, security | Code Assist, Cloud Assist, BigQuery, Looker, Databases, Security |

- Gem: trợ lý tuỳ biến lưu sẵn instruction/persona để dùng lại (chọn khi cần văn phong/format nhất quán, tách biệt từng ngữ cảnh). Saved info: ghi nhớ thông tin cá nhân giữa các cuộc chat (không dùng khi muốn tránh nhiễu từ phiên trước).
- Dữ liệu doanh nghiệp (Workspace / Gemini for Google Cloud) không dùng để huấn luyện mô hình; áp dụng bảo mật/quyền truy cập sẵn có.

### 4. Gemini for Google Cloud: ghi nhớ nhanh
Code Assist = lập trình (IDE, hoàn thành/giải thích/test code); Cloud Assist = vận hành/thiết kế hạ tầng, phân tích log; in BigQuery = NL -> SQL, khám phá dữ liệu; in Looker = BI hội thoại; in Databases = quản trị DB; in Colab Enterprise = code Python/ML trong notebook; in Security = điều tra mối đe doạ (TTP).

### 5. Câu hỏi luyện tập
1. Cần output luôn đúng một định dạng nhất định, đã có vài mẫu -> **few-shot prompting**.
2. Chatbot nội bộ phải trả lời dựa trên chính sách công ty mới nhất và dẫn nguồn, ít tốn kém -> **RAG/grounding**, không phải fine-tuning.
3. Phân tích viên muốn hỏi dữ liệu bằng tiếng tự nhiên rồi nhận SQL -> **Gemini in BigQuery**.
4. Lập trình viên muốn gợi ý code trong IDE -> **Gemini Code Assist**.
5. Cần tóm tắt và kiểm tra hiểu biết từ tập tài liệu đã có, chỉ dùng nguồn đó -> **Gemini Notebook**.
6. Cần giọng văn/format thống nhất, tái sử dụng cho nhiều tác vụ viết -> **Gem**.

### Bổ sung theo Exam Guide chính thức (mục 2.2, 3.2, 3.3)

> Nguồn: exam guide và study guide chính thức. Chi tiết xem `exam-guide-official-checklist.md`.

- **Metaprompting:** dùng prompt để hướng dẫn AI tạo, sửa hoặc diễn giải các prompt khác. (Chưa có trong deck.)
- **CoT:** dẫn LLM giải quyết vấn đề bằng ví dụ có các bước suy luận trung gian. **ReAct:** LLM vừa suy luận vừa hành động.
- **Prompt chaining** (theo study guide): hội thoại qua lại nhiều lượt trong cùng cuộc trò chuyện để giữ ngữ cảnh.
- **Gems:** trợ lý AI cá nhân hóa trong Gemini, hoạt động như template prompt và quy trình có hướng dẫn.
- **3 nguồn grounding:** first-party enterprise data, third-party data, world data (Grounding with Google Search).
- **RAG 4 bước:** Retrieval → Augmentation → Generation → Iteration (tùy chọn).
- **Offering grounding của Google Cloud:** pre-built RAG với Agent Search, RAG APIs, Grounding with Google Search.
- **Gemini Enterprise:** tìm kiếm tùy biến và agent hội thoại trên dữ liệu nội bộ (ví dụ Gemini Notebook API, multimodal search, custom agents).
